# すぐ話せる中国語

よく使う中国語を「**聞く → まねする → 話す**」で身につけるWebアプリです。
ブラウザだけで動き、インストールや有料の API キーは必要ありません。

## 機能

| タブ | できること |
| --- | --- |
| フレーズ | あいさつ・買い物・レストランなど場面別のフレーズ（43個）。🔊でお手本を聞き、🎤で発音をチェック（80点以上で「覚えた」に記録） |
| クイズ | 日本語を見て、正しい中国語を4択から選ぶ。「写真で単語」で覚えた花・動物も出題される |
| 声調 | 4つの声調（mā / má / mǎ / mà）を聞き比べる |
| 会話練習 | 場面ごとに、相手のセリフへ中国語で返事をする（くわしくは下） |
| 写真で単語 | 花や動物の写真を選ぶかカメラで撮ると、画像認識（CLIP）が見分けて中国語で教えてくれる（花20種・動物28種）。「覚えた」を押すとクイズに出る |

画面上部のスライダーで、読み上げスピードを変えられます。

### 会話練習

自己紹介・レストラン・買い物・道を尋ねる・ホテルの5つの場面があります。

- 相手のセリフは自動で読み上げられ、🔊で何度でも聞ける
- 🎤で話す（または文字で入力する）と、伝わったかを点数で判定する（75点以上で合格）
- 伝わらなかった字は赤く表示され、その字のピンインと声調のコツが出る
- **返事によって会話が分かれる**（例：学生と答えると「何を勉強しているの？」、会社員と答えると「どんな仕事？」）
- 2回まちがえるとヒント（返事の例とお手本の音声）が出る。スキップもできる
- 日本語訳はふだん隠れていて、「日本語訳を見る」を押すと表示される
- 説明の言語を日本語／中文で切り替えられる
- 終わると「1回で伝わった返事の数」が出て、一覧に記録される

## 動かし方

ブラウザは **Chrome** か **Edge** を使ってください（🎤の音声認識に必要）。

1. `index.html` をブラウザで開く
2. 🎤を使うときは、マイクの使用を許可する

マイクの許可が毎回出て面倒な場合は、ローカルサーバーで開きます。

```
py -m http.server 8000
```

ブラウザで http://localhost:8000 を開きます（VS Code の拡張機能「Live Server」でもOK）。

### 使う前に知っておくこと

- **インターネット接続：** 🎤の音声認識は、ブラウザ（Chrome / Edge）の機能で、音声はブラウザの提供元のサーバーで文字にされます。そのため🎤にはインターネット接続が必要です。「写真で単語」は、初回だけ画像認識のモデル（約150MB）のダウンロードが必要です。写真そのものは端末の中だけで解析され、送信されません
- **読み上げの音声：** パソコンに入っている中国語の音声を使います。発音がおかしい、または読み上げられないときは、Windows の **設定 → 時刻と言語 → 音声認識** で「中国語（簡体字、中国）」の音声を追加してください
- **音声認識のくせ：** 同じ発音の別の字に聞き取られることがあります（例：「两位」が「两为」になる）。この場合、正しく発音していても減点されることがあります
- **記録の保存先：** 「覚えた」や会話練習の記録は、ブラウザの中（localStorage）に保存されます。別のブラウザやパソコンには引き継がれません

### script の読み込み順

`index.html` の `<script>` は、次の順番でないと動きません。ファイルを追加するときは順番に気をつけてください。

```
data/phrases.js → data/scenarios.js → data/objects.js → app.js → talk.js → camera.js
```

- `data/` のファイルは、それを使う JS より前に読み込む（`app.js` は `data/objects.js` も使う）
- `talk.js` と `camera.js` は、`app.js` の関数（`speak()`、`similarity()`、`state` など）を使うので、`app.js` より後に読み込む
- どのファイルも同じグローバルの名前空間を使っています。新しく関数や変数を作るときは、ほかのファイルと名前がかぶらないようにしてください

## データの増やし方

コードを書かなくても、`data/` のファイルに書き足すだけで内容を増やせます。

### フレーズ（`data/phrases.js`）

```js
{ zh: "漢字", py: "ピンイン", ja: "日本語" }
```

### 写真で単語の花・動物（`data/objects.js`）

```js
{ en: "英語名", zh: "漢字", py: "ピンイン", ja: "日本語" }
```

英語名を画像認識に使うので、AIの学習し直しは不要です。

### 会話練習のシナリオ（`data/scenarios.js`）

書き方はファイル先頭のコメントにもあります。

```js
{
  id: "job",                                   // セリフの名前（分かれ道の行き先に使う）
  zh: "你是学生吗？", py: "nǐ shì xuésheng ma?", ja: "あなたは学生ですか？",
  hint: { ja: "学生か社会人かを答えよう", zh: "说你是学生还是上班族" },
  answers: [
    // [漢字, ピンイン, 日本語訳, 次のセリフの id（省略可）]
    ["是，我是学生。", "shì wǒ shì xué sheng", "はい、学生です", "study"],
    ["不是，我是公司职员。", "bú shì wǒ shì gōng sī zhí yuán", "いいえ、会社員です", "work"],
  ],
},
{ id: "study", ..., next: "why" },  // 分かれた先は next で本筋に戻す
{ id: "work",  ..., next: "why" },
```

- 返事のピンインは、**漢字1文字につき1音節**をスペースで区切って書く（伝わらなかった字の声調を教えるのに使うため）
- 「我叫＿＿。」のように `＿＿` を入れると、その部分は自由に言ってよい（名前など）
- 次に進むセリフは、返事の4番目の `id` → セリフの `next` → 配列の次のセリフ、の順で決まる
- `"end"` を行き先にすると会話が終わる
- 分かれた先のセリフには `next` を書いて本筋に戻すのを忘れないこと（書かないと配列の次、つまり別の分かれ道のセリフに進んでしまう）

## 開発の流れ

**作業ごとにブランチを切り、終わったら Pull Request でマージして消す**方式で進めます。
ブランチを短期間で使い捨てにすることで、`main` とのずれを小さくしてコンフリクトを防ぎます。

```
main ──●──────────●──────────●──
        \        /  \        /
         ●──●───     ●──●───
     feature/quiz   feature/add-phrases
```

1. 作業を始める前に `main` を最新にする
   ```
   git switch main
   git pull
   ```
2. 作業用のブランチを作る
   ```
   git switch -c feature/やること
   ```
3. 作業してコミット（何回でもOK）
   ```
   git add .
   git commit -m "何をしたか"
   ```
4. Pull Request を出す前に、相手の変更を取り込んでおく（コンフリクトがあればここで解消して動作確認）
   ```
   git switch main
   git pull
   git switch feature/やること
   git merge main
   ```
5. プッシュして、GitHub で Pull Request を作成（`feature/やること` → `main`）
   ```
   git push -u origin feature/やること
   ```
6. 相手に確認してもらい、相手が Merge する
7. マージされたら `main` に戻って最新にし、使い終わったブランチを消す
   ```
   git switch main
   git pull
   git branch -d feature/やること
   ```
   GitHub 側のブランチは、Pull Request のページの「Delete branch」で消す

### ブランチ名の付け方

| 種類 | 名前 | 例 |
| --- | --- | --- |
| 機能の追加・改善 | `feature/〜` | `feature/scenario-talk`、`feature/photo-words-quiz` |
| バグの修正 | `fix/〜` | `fix/audio-bug` |
| ドキュメント | `docs/〜` | `docs/update-readme` |

名前は英小文字とハイフンで、中身がわかるように付けます。

### コンフリクトが起きたら

2人とも機能を追加していくので、`index.html`（タブ・画面・`<script>`）、`style.css`（ファイルの最後）、`README.md`（機能一覧）は、同じ場所への追加でぶつかりやすいです。

- 「2人が同じ場所にそれぞれ追加した」コンフリクトは、**基本的に両方残す**
- ただし `<script>` の部分は、両方残すと同じファイルが2回読み込まれることがある。上の「script の読み込み順」どおりに並べ直す
- 解消したら `<<<<<<<`・`=======`・`>>>>>>>` が残っていないか検索し、ブラウザで全部のタブを触って動作を確認してからコミットする

## ルール

- `main` には直接 push しない（必ず Pull Request 経由）
- 1つのブランチでは1つの作業だけをする（関係ない変更を混ぜない）
- 自分の Pull Request は自分でマージしない（相手が確認してからマージする）
- 同じファイルを同時に大きく編集しない。触る前にひと声かける
- コミットメッセージは「何をしたか」が分かるように書く（日本語OK）
- マージ前に、ファイルに `<<<<<<<` や `>>>>>>>` が残っていないか確認する
- **有料の API（API キーが必要で料金がかかるもの）は使わない。** ブラウザの機能や、無料で端末の中で動くものを使う
- パスワードや API キーはコミットしない
