# すぐ話せる中国語

よく使う中国語フレーズを「聞く → まねする → 話す」で覚えるWebアプリです。

## 機能

- **フレーズ**：あいさつ・買い物・レストランなど場面別のフレーズ。🔊でお手本を聞き、🎤で自分の発音をチェックできます（80点以上で「覚えた」に記録）
- **クイズ**：日本語を見て、正しい中国語を4択から選びます
- **声調**：4つの声調（mā / má / mǎ / mà）を聞き比べます
- **会話練習**：レストラン・買い物・ホテルなどの場面で、相手のセリフに中国語で返事をします
  - 🎤で話すと伝わったかを判定し、伝わらなかった字を赤く表示して声調のコツを教えます
  - 2回まちがえるとヒント（返事の例とお手本の音声）が出ます
  - 説明の言語（日本語／中国語）を切り替えられます
- **写真で単語**：花や動物の写真を選ぶかカメラで撮ると、AI（画像認識 CLIP）が見分けて中国語で教えてくれます（花20種・動物28種）。画像は端末の中だけで解析し、送信しません（初回だけAIのダウンロード約150MBにインターネット接続が必要）
- 読み上げスピードの調整、覚えたフレーズの記録（ブラウザに保存）

## 動かし方

インストールは不要です。

1. `index.html` を **Chrome** か **Edge** で開く
2. 🎤（音声認識）を使うときはマイクの使用を許可する

マイクの許可が毎回出て面倒な場合は、ローカルサーバーで開きます。

```
python -m http.server 8000
```

ブラウザで http://localhost:8000 を開きます（VS Code の拡張機能「Live Server」でもOK）。

## フォルダ構成

```
.
├── README.md        … このファイル（概要・ルール）
├── index.html       … 画面の骨組み
├── style.css        … 見た目
├── app.js           … 動き（読み上げ・音声認識・クイズ）
├── talk.js          … 会話練習の動き
├── camera.js        … 写真で単語（画像認識）
├── data/
│   ├── phrases.js   … フレーズと声調のデータ
│   ├── scenarios.js … 会話練習のシナリオのデータ
│   └── objects.js   … 写真で単語の花・動物リスト
├── docs/            … 仕様メモ・設計・議事録など
├── src/             … ソースコード（今は未使用）
└── .github/         … Pull Request テンプレート
```

フレーズを増やすときは `data/phrases.js` に `{ zh: "漢字", py: "ピンイン", ja: "日本語" }` を追加するだけです。
写真で単語の花や動物を増やすときは `data/objects.js` に `{ en: "英語名", zh: "漢字", py: "ピンイン", ja: "日本語" }` を足すだけです（AIの学習し直しは不要）。

会話練習のシナリオを増やすときは `data/scenarios.js` にシナリオを追加します。書き方はファイルの先頭のコメントを見てください。返事の候補のピンインは、**漢字1文字につき1音節**をスペースで区切って書きます（発音のアドバイスで、どの字がどの音かを対応させるため）。

## 開発の流れ

**作業ごとにブランチを切り、終わったら Pull Request でマージして消す**方式で進めます。
ブランチを短期間で使い捨てにすることで、`main` とのずれを小さくしてコンフリクトを防ぎます。

```
main ──●──────────●──────────●──
        \        /  \        /
         ●──●───     ●──●───
     feature/quiz   feature/add-phrases
```

1. 作業を始める前に `main` を最新にする
   ```
   git switch main
   git pull
   ```
2. 作業用のブランチを作る
   ```
   git switch -c feature/やること
   ```
3. 作業してコミット（何回でもOK）
   ```
   git add .
   git commit -m "何をしたか"
   ```
4. プッシュして、GitHub で Pull Request を作成（`feature/やること` → `main`）
   ```
   git push -u origin feature/やること
   ```
5. 相手に確認してもらい、相手が Merge する
6. マージされたら `main` に戻って最新にし、使い終わったブランチを消す
   ```
   git switch main
   git pull
   git branch -d feature/やること
   ```

### ブランチ名の付け方

| 種類 | 名前 | 例 |
| --- | --- | --- |
| 機能の追加・改善 | `feature/〜` | `feature/quiz`、`feature/add-phrases` |
| バグの修正 | `fix/〜` | `fix/audio-bug` |
| ドキュメント | `docs/〜` | `docs/branch-rules` |

名前は英小文字とハイフンで、中身がわかるように付けます。

## ルール

- `main` には直接 push しない（必ず Pull Request 経由）
- 1つのブランチでは1つの作業だけをする（関係ない変更を混ぜない）
- 自分の Pull Request は自分でマージしない（相手が確認してからマージする）
- 同じファイルを同時に大きく編集しない。触る前にひと声かける
- コミットメッセージは「何をしたか」が分かるように書く（日本語OK）
- マージ前に、ファイルに `<<<<<<<` や `>>>>>>>` が残っていないか確認する
- パスワードや API キーはコミットしない（`.env` に書く）
